# 주간 계획·실적 현황판 — 요구사항 (작성 중)

> 상태: **요구사항 정리 중. 구현 시작 전.**
> 정리가 끝나면 이 문서를 최종본으로 다시 정리하고, 사용자 확인을 받은 뒤 그 기준으로 만든다.
> 범위: **1차만.** 1차 범위 밖 항목은 이 문서에 넣지 않는다.

## 1. 목적
어떤 양식의 원본 데이터든 셋업 화면에서 한 번 설정하면, 주기별(주간·월간) **계획·전망·실적·지연**을 같은 형태의 그래프와 표로 보여 주는 범용 현황판.
- 셋업이 다소 번거롭더라도 **엑셀만큼 유연하되 직관적으로** 설정할 수 있어야 한다.
- 결과 화면의 기준: 기존 Eng. Document(Hull) 화면(주별 막대 + 누적선 그래프, 당주/누적 요약표, 상세표).

## 2. 실행 환경
- 서버 없이 **HTML 파일 하나**를 브라우저에서 연다. 회사 데이터는 밖으로 나가지 않는다.
- 엑셀(.xlsx)·CSV를 읽는다.

## 3. 원본 데이터 구조
- **한 행 = 관리 단위 1개.** 기본 이름은 "문건"이며, 단위 이름은 바꿀 수 있다(예: 도면, 장비, 패키지).
- Stage별 날짜는 **각각 열**로 있다(예: IFR 초기계획 / IFR 확정계획 / IFR 전망 / IFR 실적 / IFC …).
- 계획 날짜는 **초기계획·확정계획 두 개**일 수 있다(하나만 있어도 된다).
- 행마다 **수량 열**, **가중치 열**이 있을 수 있다.

## 4. 데이터 셋업
1. 파일 올리기 → 시트·머리글 행 선택.
2. **열 역할 지정 — 역할 목록과 이름은 고정하지 않는다.**
   - 역할 종류: 고유키 / 분류 / 날짜(Stage × 날짜 종류) / 가중치 / 수량.
   - 분류는 원하는 만큼 추가하고 이름을 직접 붙인다(예: 문서번호, Discipline, 기능코드, 도종, 제출처, 승인코드, Vendor — 모두 예시일 뿐 명칭은 바뀔 수 있다).
   - Stage 이름, 날짜 종류 이름(초기계획·확정계획·전망·실적), 수량 이름(예: 도면 매수)도 모두 바꿀 수 있다.
3. **그룹핑**: 분류 값을 묶어 합계로 표기(예: 전장설계 → 기능코드 00·00·00 합계).
4. **Progress 산출 로직**(별도 설정 영역):
   - 가중치가 Stage별·문건별·Discipline(분류)별로 다를 수 있다.
   - 예: Discipline A는 IFR 40 / IFC 40 / IFI 20, Discipline B는 다른 비율, 특정 문건은 가중치 열 사용.
5. **날짜 적용 규칙**(설정 가능, 아래 6장 기본값):
   - 계획으로 초기계획·확정계획 중 무엇을 쓸지.
   - 전망이 비어 있을 때 무엇으로 대신할지.
   - 실적이 있을 때 전망 집계에 실적을 넣을지.
6. **표시 이름 설정**: 그래프·표에 나오는 모든 역할 이름은 4-2에서 붙인 이름을 따른다.
7. **주기 설정**: 주 시작 요일 기본 **월요일**, 변경 가능. 주간/월간 전환.
8. 셋업 설정은 저장해 두고 다음 데이터에 그대로 다시 쓴다.

## 5. 집계 방식 (세 가지를 각각 볼 수 있다)
| 집계 | 내용 |
|---|---|
| 건수 | Stage를 통과한 단위 개수 |
| Progress | 4-4의 가중치를 적용한 진도 |
| 수량 | 수량 열 합계 |

## 6. 날짜 적용 기본값
- **계획**: 셋업에서 고른 계획(초기 또는 확정).
- **전망**: 실적이 있으면 **실적일**, 없으면 전망일, 전망도 없으면 **계획일**.
  → Cut-off까지 누적 전망 = 누적 실적, Cut-off 이후는 전망이 이어진다(기존 화면 그래프와 같은 모양).
- **실적**: 실적일.

## 7. 지연·선진행·차이 (Cut-off 기준, Stage별)
- **지연**: 계획일 ≤ Cut-off 인데 Cut-off까지 실적이 없는 것의 수량.
- **선진행**: 계획일 > Cut-off 인데 Cut-off까지 실적이 발생한 것의 수량.
- **차이(Dev.)**: 계획 − 실적.

## 8. 현황판 화면
- 필터: 분류 열, Stage, 표시 범위(From–To), 주기, 집계 방식.
- **그래프**: 주기별 계획/전망/실적 막대 + 누적선, Cut-off 표시선.
- **요약표**: 당주(계획·전망·실적·차이) / 누적(계획·전망·실적·차이·선진행·지연) / 향후 2주 계획 / Remark.
  - **Remark 칸은 비워 둔다.** (기존 REJECT 건수 표시는 없앤다.)
- **상세표**: 분류 → Stage 등 여러 단계로 나눠 보기(나누는 순서 선택).
- **원본 데이터 점검**: 날짜 누락, Stage 순서 역전, 중복 키, 날짜 형식 오류, 예외 처리 목록.

## 9. 지난주·이번주 데이터 보관과 변경 점검
- 툴이 **지난주와 이번주 데이터를 보관**한다.
- 새 데이터를 올리면 **이전 Cut-off 이전의 실적이 바뀌었는지** 점검해 보여 준다(실적일 변경·삭제, 행 추가·삭제).

## 10. 내보내기
- 요약표·상세표 엑셀/CSV 내보내기는 **하지 않는다.**

## 11. 1차 범위에서 제외
- 관리 항목 간 연결(스케줄 activity ↔ MDR 등), Level2, VDR/DP 별도 화면, REJECT 건수.

## 12. 아직 정하지 않은 것
- [ ] 지연 판정 시 Cut-off 이후 실적은 "실적 없음"으로 보는지(현재 그렇게 해석).
- [ ] 초기계획·확정계획이 둘 다 있을 때, 그래프에 둘 다 보여 줄지 하나만 고를지.
- [ ] 차이 표시 부호: 기존 화면은 계획 1·실적 0일 때 -1로 보인다. 같은 부호(실적이 모자라면 음수)로 할지.
- [ ] 데이터·설정 보관 위치: 브라우저 저장소만 쓸지, 설정/스냅샷 파일로도 저장·불러오기 할지(브라우저 데이터 삭제 대비).
- [ ] 보관 범위: 지난주·이번주 2개만인지, 더 많이 보관할지.
