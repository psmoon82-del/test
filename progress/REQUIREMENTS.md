# 주간 계획·실적 현황판 — 요구사항 (작성 중)

> 상태: **요구사항 정리 중. 구현 시작 전.**
> 정리가 끝나면 이 문서를 최종본으로 다시 정리하고, 사용자 확인을 받은 뒤 그 기준으로 만든다.
> 범위: **1차만.** 1차 범위 밖 항목은 이 문서에 넣지 않는다.

## 1. 목적
어떤 양식의 원본 데이터든 셋업 화면에서 한 번 설정하면, 주기별(주간·월간) **계획·전망·실적·지연**을 같은 형태의 그래프와 표로 보여 주는 범용 현황판.
- 셋업이 다소 번거롭더라도 **엑셀만큼 유연하되 직관적으로** 설정할 수 있어야 한다.
- 결과 화면의 기준: 기존 Eng. Document(Hull) 화면(주별 막대 + 누적선 그래프, 당주/누적 요약표, 상세표).

## 2. 실행 환경
- 서버 없이 **HTML 파일 하나**를 브라우저에서 연다. 회사 데이터는 밖으로 나가지 않는다.
- 엑셀(.xlsx)·CSV를 읽는다.

## 3. 원본 데이터 구조
- **한 행 = 관리 단위 1개.** 기본 이름은 "문건"이며, 단위 이름은 바꿀 수 있다(예: 도면, 장비, 패키지).
- Stage별 날짜는 **각각 열**로 있다(예: IFR Plan / IFR Forecast / IFR Actual / IFC Plan / …).
- 행마다 **수량 열**이 있을 수 있다(예: 도면 매수, DP 건수).
- 분류 열(Discipline, 기능코드, 도종, 제출처, 승인코드, Vendor 등)은 파일마다 다르므로 셋업에서 고른다.

## 4. 데이터 셋업
1. 파일 올리기 → 머리글 행·시트 선택.
2. **열 역할 지정**: 고유키(문건번호), 분류 열들, Stage 정의(Stage 이름 + Plan/Forecast/Actual 열), 수량 열(선택).
3. **그룹핑**: 분류 값을 묶어 합계로 표기(예: 전장설계 → 기능코드 00·00·00 합계).
4. **Progress 산출 로직**(별도 설정 영역):
   - 가중치가 Stage별·문건별·Discipline별로 다를 수 있다.
   - 예: Discipline A는 IFR 40 / IFC 40 / IFI 20, Discipline B는 다른 비율, 특정 문건은 별도 가중치 열 사용.
5. **표시 이름 설정**: 그래프·표에 나오는 역할 이름(Plan/Forecast/Actual, Stage, 분류 이름 등)을 원하는 이름으로 바꾼다.
6. **주기 설정**: 주 시작 요일 기본 **월요일**, 변경 가능. 주간/월간 전환.
7. 셋업 설정은 저장해 두고 다음 데이터에 그대로 다시 쓴다.

## 5. 집계 방식 (세 가지를 각각 볼 수 있다)
| 집계 | 내용 |
|---|---|
| 건수 | Stage를 통과한 단위 개수 |
| Progress | 4-4의 가중치를 적용한 진도 |
| 수량 | 수량 열 합계 |

## 6. 지연·선진행 정의 (Cut-off 기준, Stage별)
- **지연**: 계획일 ≤ Cut-off 인데 Cut-off까지 실적이 없는 것의 수량.
- **선진행**: 계획일 > Cut-off 인데 Cut-off까지 실적이 발생한 것의 수량.

## 7. 현황판 화면
- 필터: 분류 열(Discipline·Stage·기능·도종 등), 표시 범위(From–To), 주기, 집계 방식.
- **그래프**: 주기별 Plan/Forecast/Actual 막대 + 누적선, Cut-off 표시선.
- **요약표**: 당주(Plan·Forecast·Actual·차이) / 누적(Plan·Forecast·Actual·차이·선진행·지연) / 향후 2주 계획 / Remark.
- **상세표**: 분류 → Stage 등 여러 단계로 나눠 보기(나누는 순서 선택).
- **원본 데이터 점검**: 날짜 누락, Stage 순서 역전, 중복 키, 날짜 형식 오류, 예외 처리 목록.

## 8. 지난주·이번주 데이터 보관과 변경 점검
- 툴이 **지난주와 이번주 데이터를 보관**한다.
- 새 데이터를 올리면 **이전 Cut-off 이전의 실적이 바뀌었는지** 점검해 보여 준다(실적일 변경·삭제, 행 추가·삭제).

## 9. 내보내기
- 요약표 엑셀/CSV 내보내기는 **하지 않는다.**

## 10. 1차 범위에서 제외
- 관리 항목 간 연결(스케줄 activity ↔ MDR 등), Level2, VDR/DP 별도 화면.

## 11. 아직 정하지 않은 것
- [ ] 지연 판정 시 Cut-off 이후 실적은 "실적 없음"으로 보는지(현재 그렇게 해석).
- [ ] Forecast가 비어 있을 때 Plan으로 대신하는지.
- [ ] 차이(Dev.)를 Forecast–Actual로 할지, Plan–Actual로 할지.
- [ ] Remark 칸에 무엇을 보여 줄지(기존 화면의 REJECT 건수 등 → 어떤 열 기준인지).
- [ ] 상세표 CSV 내보내기가 필요한지.
- [ ] 데이터·설정 보관 위치: 브라우저 저장소만 쓸지, 설정/스냅샷 파일로도 저장·불러오기 할지(브라우저 데이터 삭제 대비).
- [ ] 보관 범위: 지난주·이번주 2개만인지, 더 많이 보관할지.
