# OPIc 연습 도구 — 인수인계 (2026-10-03)

새 대화창에서 이어서 작업하기 위한 문서다. 새 창의 Claude는 이 문서를 먼저 끝까지 읽고, **바로 만들지 말고** 아래 "처음 할 일"부터 시작한다.

## 1. 무엇을 만드나

Atlas에 정리된 소유자 기록을 활용해 **OPIc 시뮬레이터 / 연습 / 스크립트 작성 도구**를 만든다.

- 목표: OPIc 등급을 **IM → IH**로 되돌리기(올해 안).
- 소유자 상황(Atlas 기록 기준): OPIc IH를 5년 넘게 유지하다 3년 전부터 IM. 회사에서 회의·이메일·기술 자료 등 영어가 전반적으로 필요하다. 혼자가 아니라 AI 도구와 함께 공부하고 싶어 한다. 활동 중 영어는 에너지를 빼는 쪽이라고 답했다(재미와 부담을 줄이는 설계가 중요).
- **Atlas는 그대로 둔다.** 필요한 부분만 가져와 **별도의 새 앱**으로 만든다(`opic/` 폴더, 새 Artifact).

## 2. 소유자와 일하는 방식 (지켜야 함)

- **먼저 논의하고, 정리되면 수정한다.** 설계를 제안하고 확인받은 뒤 만든다.
- 소유자가 정할 것은 **선택형으로 묻는다**(AskUserQuestion, 추천안은 첫 번째에 "(Recommended)"). 소유자가 먼저 말하고 싶어 하면 질문을 접고 듣는다.
- **가장 대표적이고 신뢰할 수 있는 방식**을 따른다. OPIc은 ACTFL 공식 기준과 실제 시험 형식에 맞춘다.
- 한국어는 담백하게. 번역투·감성 조어 피하기.
- **솔직하게 평가한다.** 소유자는 "이쁜 쓰레기"를 가장 싫어한다. 실제로 매일 쓰게 되는지가 기준이다.

## 3. OPIc에 대해 (설계 전에 최신 형식을 다시 확인할 것)

- ACTFL 주관, 컴퓨터 기반 말하기 시험. 순서: **Background Survey**(직업·거주·여가·취미·운동·여행 등 선택) → **Self Assessment**(난이도 1~6 선택) → 오리엔테이션 → 약 15문항, 40분 안팎. 중간에 난이도 재조정 질문이 있다.
- 질문은 화면에 글로 나오지 않고 **음성으로 들려준다(최대 2번)**. 답변 시간은 문항별로 따로 정해져 있지 않다.
- 보통 한 주제에 2~3문항 묶음: **묘사 → 습관·경향 → 과거 경험(특별한 일)**. 그 밖에 **비교·변화**, **롤플레이**(질문하기, 문제 상황 해결), **돌발 주제**(Survey에서 안 고른 주제)가 나온다.
- 등급: NL·NM·NH · IL·IM1~3·**IH** · AL.
- IH에 필요한 것(ACTFL Intermediate High 기준): 문장을 넘어 **문단 수준**으로 이어 말하기, **과거·현재·미래 시제를 넘나들며 이야기하기**, 롤플레이에서 **예상 밖 문제(complication)를 처리하기**. 어순·시제가 가끔 무너지는 정도는 허용된다.
- **외운 티가 나는 답은 감점된다.** 완성 대본을 통째로 외우기보다 이야기 재료 + 답변 틀 + 핵심 표현을 익히고, 상황마다 다시 조립해 말하는 연습이 맞다.

## 4. 설계 초안 (확정 아님, 새 창에서 논의)

1. **내 설정**: 실제 시험처럼 Background Survey 항목을 고른다. 소유자의 실제 생활과 맞는 주제를 추천한다(Atlas 기록 근거). 목표 등급과 Self Assessment 단계도 정한다.
2. **이야기 재료 → 답변 틀**: 주제마다 Atlas 기록과 짧은 한국어 인터뷰로 실제 경험(장면, 숫자, 감정)을 모으고, IH 수준의 답변 틀(도입 → 묘사 → 구체적 사건 → 느낌 → 마무리)과 핵심 표현으로 정리한다. 어휘는 소유자가 실제로 쓸 만한 수준으로 맞춘다.
3. **연습 모드**: 한 문항씩. 질문을 음성으로 들려주고(2번까지), 소유자가 말하고, 받아 적은 글로 피드백한다(길이, 시제, 문단 연결, 자주 틀리는 표현). 같은 질문 다시 말하기.
4. **모의고사**: Survey와 난이도에 맞춘 15문항 흐름. 끝나면 ACTFL 기준으로 항목별 피드백과 추정 등급을 준다. 추정치일 뿐이라는 점을 밝힌다.
5. **기록과 진척**: 약한 유형(롤플레이, 과거 시제 등), 표현 은행, 연습 횟수. 매일 10~15분처럼 짧게 이어 갈 수 있게.

**아직 정하지 않은 것**
- 음성: 말하기를 어떻게 받나(브라우저 음성 인식, 녹음 후 받아쓰기, 직접 타이핑 대안). **Artifact 런타임에서 마이크·음성 인식·음성 합성이 되는지 먼저 확인한다**(`artifact-capabilities` 스킬을 먼저 불러서 마이크 capability와 사용법 확인). 안 되면 타이핑 + 질문 음성(speechSynthesis)으로 시작.
- 한국어 비중: 설명과 피드백을 한국어로 할지, 영어로 할지.
- 첫 범위: 연습 모드 + 답변 틀부터 / 모의고사까지 한 번에.
- 하루 루틴과 알림(Atlas의 주간 Routine처럼).

- Atlas Artifact: https://claude.ai/artifact/AfkbQn3BB16ocdAapZ2oXU
- `ArtifactData` 도구, `url` = 위 주소, `collection` = `data/users/me`. `action: "list"`, `out_dir`로 스크래치 폴더에 받은 뒤 필요한 것만 읽고, **다 쓰면 임시 파일을 지운다.**

- 중복된 사실이 많다(같은 내용이 여러 번). 읽을 때 합쳐서 본다.
- **새 앱에서 Atlas 저장소에 쓰지 않는다.**

## 7. 기술 메모

- claude.ai Artifact, 런타임 contract 0.2.60. **새 Artifact로 publish한다(Atlas URL에 덮어쓰지 말 것).**
- 오디오는 크다. 문서당 256KiB 제한이 있으니 녹음 파일은 저장하지 않거나 별도 방식을 확인하고, 기본은 **받아 적은 글만** 저장한다.
- AI 오류: `empty_completion`이면 다음 요청을 가벼운 방식으로, `invalid_json`이면 산문 답 살리기. 오류 코드는 화면에 보이게.
- 빌드 뒤 `node --check dist/app.check.js`가 통과할 때만 publish.
- 테스트: `CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, `playwright install` 금지, `page.wait_for_timeout` 사용.
- 커밋 메시지·코드에 모델 이름을 넣지 않는다. PR은 요청이 있을 때만.
